## 実装とデータ

`NOTTA_SERVICE_ENABLED=yes` のとき、新しい画面と `/api/service/` を使用します。旧APIはこのモードでは公開しません。未設定時は現行の入口を維持します。

既存の users / projects / tasks / applications / revisions を使用し、service_schema.py の13表を追加します。本番リクエストからの自動DDLはありません。`migrate_service.py --expected-host <確認した接続先> --apply` で明示的に移行します。既存表の削除や列の書換えはありません。

主なファイル：

- `service_core.py`：認証、企画、AI利用枠、公開・応募・共同作業。
- `service_providers.py`：Resend / Gemini のサーバー側通信。自動再送なし。
- `service_stripe.py`：Stripe Hosted Checkoutと月額契約。固定税込3,000円の価格、環境、本人の契約、請求、実際に成功した支払と返金を照合。戻り画面や契約状態だけでは有料化しません。通知の署名・時刻・環境・重複を検証し、APIから最新状態を読みます。
- `service_billing.py`：旧決済の内部検証用実装。新サービスの入口では使用せず、旧通知URLも受け付けません。
- `notta_service.py`：認証と権限を確認する入口。下書き・会話は本人限定、応募と提出は本人と企画者限定。
- `static/service.*`：料金、認証、原稿編集、募集、共同作業、契約管理、会社・規約ページ。
- `service_ops.py`：未処理の返金申出、不明なAI依頼・決済、利用費、入金と返金を確認する運用レポート。決済環境を併記し、検証環境の支払いを獲得実績と分けます。

## 外部接続の設定

必要項目は `.env.example` を参照してください。実値はGitに入れず、該当環境の安全な設定欄で指定します。検証環境には本番と分けたDB・認証鍵・Stripeの独立したSandboxを使います。専用Vercelプロジェクト `notta-sandbox-20261023` はホスティング上のproduction区分ですが、決済はSandboxに固定しており、既存本番とは別です。

1. Resend：正しい会社チームでmaora.co.jpの検証済みドメインと実DNSの一致を確認済み。ノッタ専用・会社ドメイン送信のみのキーを検証環境へ保存し、実際の認証メール到着を確認しました。公開サイトで本人がメール認証してログインする試験は残っています。Google WorkspaceのMXは変更しません。
2. Gemini：有料APIのデータ取扱いと利用枠を確認してから `NOTTA_AI_ENABLED=yes`。モデルは `gemini-3.5-flash-lite`。通常の相談は入力長と出力トークンを制限し、保守的な費用を予約します。
3. 検索：検索語句を利用者が確認した場合だけ `gemini-2.5-flash` のGoogle Searchへ送り、企画や会話、応募データは検索へ渡しません。検索結果は `gemini-3.5-flash-lite` の通常生成で原稿へ反映する構成です。入力は検索8,192・通常生成32,768トークン、出力は検索1,000・通常生成6,000トークンを上限に確認します。ただし実接続で追加の `toolUsePromptTokenCount` を検出し、ツール文脈の費用上限は確認できていません。検索の公開フラグは無効、`NOTTA_SEARCH_LIMIT_VERIFIED=no` を維持し、費用上限が未確認の状態では有効にしません。
4. Stripe：既存Mobbyアカウントを使い、販売者はMAORA株式会社を維持する方針です。現在の登録は個人事業のため、正式名義は本人が本番課金前の最後に修正します。サポート問い合わせは送信しません。名義と販売者表示の整合を確認してから本番課金を始めます。独立Sandboxでは税込総額3,000 JPY、month・1か月ごと・licensedの固定価格を設定済み。Priceのtax_behaviorはinclusiveまたはunspecifiedだけを許可し、Checkoutの自動税・プロモコード・Adaptive Pricingを無効化します。申込み・契約・請求の税、割引、送料、通貨と小計・総額を照合します。Hosted Checkoutとflexible Billingを使い、無料体験ではカードを求めません。
5. Stripe通知URLは `<正規origin>/api/service/stripe/webhook`。Checkout、契約、請求、支払、返金の通知を受信し、署名鍵を設定します。制限付きAPIキーにはAccount・Price・Invoice・InvoicePayment・PaymentIntent・Charge・Refundの読取、Checkout SessionとSubscriptionの読取・作成/更新に必要な権限だけを付けます。返金の実行権限はアプリへ付けません。ブラウザーには秘密鍵を返しません。
6. 本番決済は会社の電話番号と販売者表示を確認し、`NOTTA_LEGAL_VERIFIED=yes` にしてから有効化します。
7. 通知経路はStripeから認証画面やリダイレクトを挟まずに到達できる必要があります。元のPreviewの期限付き共有リンクはcookieなしPOSTが307/401になり、直接通知には使えませんでした。その共有は失効済みです。明示承認を受けた専用サイトの正規aliasだけに、一時的な `alias-protection-override` を作成して直接通知を検証しました。試験後に専用通知先を無効化し、公開例外を削除済みです。cookieなしGETは認証への302、通知POSTはVercel保護の401となり、aliasに公開例外がないことを確認しました。中間のDeployment URLと既存本番の保護は維持しています。

独立したStripe Sandboxで購入・更新・支払失敗・解約・返金・通知を検証します。更新試験にはTest Clockを利用し、実際の入金と区別します。実課金を伴う限定試験は、支払う人・金額・返金手順を合意してから別途実施します。[Stripeの検証環境](https://docs.stripe.com/testing-use-cases)

Geminiのプロジェクト別課金上限には反映の遅れがあるため、アプリの事前予約・受付制限も維持します。既存の共有プロジェクトの上限は他用途に影響するため変更しません。実AIの3企画は検索なしで確認済みです。検索の実接続1回は費用上限が未確認の応答を検出したため後続の原稿生成を行わず、不明な依頼として100円の予約を保持しています。再検索はしていません。[Googleの課金上限](https://ai.google.dev/gemini-api/docs/billing/#spend-caps)
