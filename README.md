## 提供する内容

- 無料：メール認証、本人の企画に沿ったAIとの対話、企画概要・達成条件・最初の成果物・役割2〜3種類・募集文の作成、保存・手編集・コピー。
- 有料：月額3,000円（税込総額）。同時に1企画。募集公開、応募比較、担当決定、文章・URLでの成果提出、企画者による確認と貢献記録。企画に14日の強制終了はありません。参加者は無料です。
- AIの上限：無料10回と検索1回、有料は契約月100回と検索10回。受付上限は無料30人・有料5人。月3,000円の費用枠に有料分と受付済みの無料体験分を予約し、残額が足りない場合は新規受付を停止します。
- 解約：次回更新停止、支払済み期間まで利用。初回支払いから7日以内の申出で初回料金を全額返金。申出は記録し、MAORAがStripeで返金を確認・実施します。
- 販売者：MAORA株式会社（マオラ）、長谷川峻平、shumpei.hasegawa@maora.co.jp、090-9325-5945、https://www.maora.co.jp/ 。

## 実装とデータ

`NOTTA_SERVICE_ENABLED=yes` のとき、新しい画面と `/api/service/` を使用します。旧APIはこのモードでは公開しません。未設定時は現行の入口を維持します。

既存の users / projects / tasks / applications / revisions を使用し、service_schema.py の13表を追加します。本番リクエストからの自動DDLはありません。`migrate_service.py --expected-host <確認した接続先> --apply` で明示的に移行します。既存表の削除や列の書換えはありません。

主なファイル：

- `service_core.py`：認証、企画、AI利用枠、公開・応募・共同作業。
- `service_providers.py`：Resend / Gemini のサーバー側通信。自動再送なし。
- `service_stripe.py`：Stripe Hosted Checkoutと月額契約。固定税込3,000円の価格、環境、本人の契約、請求、実際に成功した支払と返金を照合。戻り画面や契約状態だけでは有料化しません。通知の署名・時刻・環境・重複を検証し、APIから最新状態を読みます。
- `service_billing.py`：旧決済の内部検証用実装。新サービスの入口では使用せず、旧通知URLも受け付けません。
- `notta_service.py`：認証と権限を確認する入口。下書き・会話は本人限定、応募と提出は本人と企画者限定。
- `static/service.*`：料金、認証、原稿編集、募集、共同作業、契約管理、会社・規約ページ。
- `service_ops.py`：未処理の返金申出、不明なAI依頼・決済、利用費、入金と返金を確認する運用レポート。決済環境を併記し、検証環境の支払いを獲得実績と分けます。

## 外部接続の設定

必要項目は `.env.example` を参照してください。実値はGitに入れず、該当環境の安全な設定欄で指定します。プレビューには本番と分けたDB・認証鍵・Stripeの独立したSandboxを使います。

1. Resend：正しい会社チームでmaora.co.jpの検証済みドメインと実DNSの一致を確認済み。ノッタ専用・会社ドメイン送信のみのキーをプレビューへ保存。実際の認証メール到着を確認してから `NOTTA_MAIL_VERIFIED=yes` にします。Google WorkspaceのMXは変更しません。
2. Gemini：有料APIのデータ取扱いと利用枠を確認してから `NOTTA_AI_ENABLED=yes`。モデルは `gemini-3.5-flash-lite`。通常の相談は入力長と出力トークンを制限し、保守的な費用を予約します。
3. 検索：検索語句を利用者が確認した場合だけ別リクエストに送り、企画や会話、応募データは検索へ渡しません。Google Searchは1回の呼出しで複数の有料検索を行うため、提供側の利用制限を確認するまでは `NOTTA_SEARCH_LIMIT_VERIFIED=no` のままにします。費用上限が未検証の状態で有効にしません。
4. Stripe：既存Mobbyアカウントを使い、販売者はMAORA株式会社を維持する方針です。現在の登録は個人事業のため、本番課金前にStripeへ法人名義への正式な変更方法と既存契約への影響を確認します。アカウント名やサイト表記だけを変更して本番課金を始めません。独立Sandboxでは税込総額3,000 JPY、month・1か月ごと・licensedの固定価格を設定済み。Priceのtax_behaviorはinclusiveまたはunspecifiedだけを許可し、Checkoutの自動税・プロモコード・Adaptive Pricingを無効化します。申込み・契約・請求の税、割引、送料、通貨と小計・総額を照合します。Hosted Checkoutとflexible Billingを使い、無料体験ではカードを求めません。
5. Stripe通知URLは `<正規origin>/api/service/stripe/webhook`。Checkout、契約、請求、支払、返金の通知を受信し、署名鍵を設定します。制限付きAPIキーにはAccount・Price・Invoice・InvoicePayment・PaymentIntent・Charge・Refundの読取、Checkout SessionとSubscriptionの読取・作成/更新に必要な権限だけを付けます。返金の実行権限はアプリへ付けません。ブラウザーには秘密鍵を返しません。
6. 本番決済は会社の電話番号と販売者表示を確認し、`NOTTA_LEGAL_VERIFIED=yes` にしてから有効化します。
7. 通知経路はStripeから認証画面やリダイレクトを挟まずに到達できる必要があります。Vercelの保護設定を一括で無効化せず、通知経路と正規URLを決めてから実配信を確認します。承認を受けた4時間限定のbranch共有リンクを試しましたが、cookieなしPOSTは共有クエリで307、共有tokenのヘッダー指定で401でした。Stripeの直接通知には使えないため、専用通知先は作成後に配信停止し、決済公開も停止したままです。

独立したStripe Sandboxで購入・更新・支払失敗・解約・返金・通知を検証します。更新試験にはTest Clockを利用し、実際の入金と区別します。実課金を伴う限定試験は、支払う人・金額・返金手順を合意してから別途実施します。[Stripeの検証環境](https://docs.stripe.com/testing-use-cases)

Geminiのプロジェクト別課金上限には反映の遅れがあるため、アプリの事前予約・受付制限も維持します。既存の共有プロジェクトの上限は他用途に影響するため変更しません。実接続の3企画は検索を無効にして先行します。[Googleの課金上限](https://ai.google.dev/gemini-api/docs/billing/#spend-caps)

## 検証結果（2026年10月23日）

- 全85項目が合格。Stripe32、運用集計2、メール通信3、新機能26、既存API・WSGI・Postgres変換22項目。Stripe公式SDK 15.6.1の通信境界も含みます。実SandboxのAccount・Price読取でも設定の検証を通過しました。未払い申込みの再開リンクは最新Sessionの金額・所有者・状態を確認できたときだけ表示します。
- 会社メールから本人のGmail受信箱への実到着を確認。本人所有の3つのメール別名で認証を試し、コードの再使用と実時間で10分経過後の失効を確認。コードは自社ローカル試験の送信境界で一時メモリに計測し、通常の認証処理へ渡しました。公開Previewのブラウザー上の認証試験とは分けます。
- 実Geminiで料理・音楽・写真の3企画と条件変更を計6回実行し、保存後の再読込、同じ依頼の再実行による二重利用の防止、利用枠と費用記録を確認。保守的な台帳費用は6円。募集文に締切を入れ忘れた例があり、公開前の内容確認は必要です。
- 独立Stripe Sandboxで実Hosted Checkoutを1件作成。テスト用カードで成功し、JPY・総額3,000円、追加税・割引・送料なし、InvoicePayment・PaymentIntent・Chargeまで実APIで照合して隔離DBのACTIVEを確認。購入画面から`/billing/return`へ戻ることも確認しました。ブラウザーは未認証のため、公開Previewでのログインを含む一連の購入試験とは分けます。実入金・顧客獲得には数えません。
- 同じSandbox契約で次回更新停止後の期限維持、返金申出1件の受付、Dashboardでの3,000円全額返金を確認。実APIの再照合で返金COMPLETED・有料権限停止・返金申出完了になりました。アプリの制限付きキーに返金実行権限は付けていません。
- 実Postgres接続で2回目以降の支払照合が失敗する行比較を修正。列名を明示して読み取り、Postgres形式の回帰を追加しました。
- Postgresの集計で同じ列名が重なって入金合計が上書きされる問題と、SUMのDecimal値によるJSON出力失敗を修正。入金、完了返金、保留返金を分けて集計します。
- 返金が保留から失敗・拒否に変わった際、ほかに保留・完了返金や実返金額がなければ支払済み期間の利用権限が復帰するよう修正。完了した返金などが残る場合は停止を維持することを確認。
- Gemini 3.5 Flash-Lite以降で非推奨のtemperature指定を削除し、既存テストを確認。
- 独立したNeon検証ブランチ `notta-monthly-20261023` で追加表と実行用ロールを確認。企画保存→応募→担当決定→提出→成果確認を通過。本番DBは未変更。
- ブラウザーで架空の別アカウントを使い、認証→企画作成→編集・保存→再訪→月額条件の表示→募集→応募→担当決定→提出→確認を検証。PC 1280px / スマホ390pxで確認。
- 決済処理の内部検証に加え、実Sandboxの購入と手動API照合は上記の範囲で確認済みです。自動通知配信・更新等の残る実接続試験は別途確認します。内部検証や手動照合を、Stripeからの直接通知成功として扱いません。
